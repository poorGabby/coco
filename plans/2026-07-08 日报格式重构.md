# 日报格式重构计划

## Context

当前日报是简单的 Markdown 表格（4列：指标/昨日/前日/环比），通过飞书 `msg_type: "text"` 发送，无分析、无分组、无可折叠卡片。需要对标同类助手的日报风格，实现含概要、深度分析、可折叠模块的专业日报，用飞书交互式卡片消息呈现。

## 目标架构

```
Amplitude CSV → ChartSnapshot[] → Gemini 分析 → DailyAnalysis
                                         ↓
                              card.ts 构建飞书卡片 JSON
                                         ↓
                              sendCardToChat / replyWithCard
```

## 文件清单

### 1. 新增 `apps/hermes/src/analyze.ts` — Gemini 结构化分析

**类型定义：**
```typescript
type DailyAnalysis = {
  alertCount: number;
  watchCount: number;
  summary: string;           // 概要段落
  alerts: AlertItem[];       // 🔴 警报
  watches: WatchItem[];      // 🟡 关注项
  hypotheses: string;        // 💡 分析假设 & 下一步
};
type AlertItem = { title: string; value: string; summary: string; deepAnalysis: string };
type WatchItem = { title: string; value: string; analysis: string };
```

**核心函数：** `analyzeDailySnapshots(env: Env, snapshots: ChartSnapshot[]): Promise<DailyAnalysis>`
- 将 ChartSnapshot[] 序列化为结构化上下文
- 调用 Gemini，要求输出 JSON 格式（含 `summary`、`alerts[]`、`watches[]`、`hypotheses`）
- 解析 JSON 并校验
- 解析失败时 fallback 为纯文本分析

**关键设计决策：**
- Gemini prompt 用 `response_mime_type: "application/json"` 让模型直接输出 JSON（Gemini API 支持）
- 需要在 `llm.ts` 新增 `generateGeminiJson<T>()` 函数
- 告警判定标准写进 prompt：wow 跌幅 > 15% 或 vs7dAvg 偏离显著 → alert

### 2. 新增 `apps/hermes/src/card.ts` — 飞书卡片构建

**核心函数：** `buildDailyCard(analysis: DailyAnalysis, snapshots: ChartSnapshot[], dateLabel: string): FeishuCardV2`

**卡片结构（JSON 2.0）：**
```
┌─ Header: blue ──────────────────────────┐
│  📊 Furever 每日简报 — 2026-06-29        │
│  🔴 N 个警报  🟡 M 个关注               │
├──────────────────────────────────────────┤
│  [markdown] 概要段落                      │
├──────────────────────────────────────────┤
│  ▶ 📊 核心指标（collapsible_panel）       │
│    [markdown] 指标表格                    │
│    注：lark_md 不支持表格，改用对齐文本    │
├──────────────────────────────────────────┤
│  ▶ 🔴 警报详情（collapsible_panel）       │
│    每个 alert：title + 概要 + 深度分析     │
├──────────────────────────────────────────┤
│  ▶ 🟡 关注项（collapsible_panel）         │
│    每个 watch item                        │
├──────────────────────────────────────────┤
│  ▶ 💡 分析假设 & 下一步（collapsible）    │
│    [markdown] hypotheses                  │
└──────────────────────────────────────────┘
```

**关键设计决策：**
- 使用飞书卡片 JSON 2.0（`schema: "2.0"`），支持 `collapsible_panel` 组件
- `lark_md` 不支持 markdown 表格，核心指标改用**等宽字体对齐文本** 或 飞书原生 `table` 组件
- 每个告警的深度分析独立成段，用 `<font color='red'>` 标记关键数据
- 卡片总大小控制在 30KB 以内（飞书硬限制）

### 3. 修改 `apps/hermes/src/llm.ts` — 新增 JSON 结构化输出

**新增函数：**
```typescript
export async function generateGeminiJson<T>(
  env: Env, systemPrompt: string, userPrompt: string
): Promise<T>
```
- 复用现有 `httpsPostJson`
- 设置 `response_mime_type: "application/json"`
- 解析返回 JSON，类型安全

### 4. 修改 `apps/hermes/src/feishu.ts` — 新增卡片发送

**新增函数：**
```typescript
export async function sendCardToChat(env: Env, chatId: string, card: object): Promise<void>
export async function replyWithCard(env: Env, messageId: string, card: object): Promise<void>
```
- `msg_type: "interactive"`
- `content` = `JSON.stringify(card)`
- 复用现有 `feishuPost` / token 管理

### 5. 修改 `apps/hermes/src/report.ts` — 新增卡片日报

- 保留 `buildReportMarkdown`、`generateReport` 不变（`/hermes/report` 预览、CLI 仍用）
- 新增 `generateDailyReport(env: Env): Promise<object>` — fetch → analyze → buildCard

### 6. 修改 `apps/hermes/src/index.ts` — 端点适配

- `/hermes/daily` → 调用 `generateDailyReport`，用 `sendCardToChat` 发送
- `/feishu/events` 收到"日报" → 调用 `generateDailyReport`，用 `replyWithCard` 发送
- 其他端点不变

## 高风险项

1. **Gemini JSON 输出不稳定** — 模型可能输出非 JSON 或字段缺失。对策：用 `response_mime_type` 约束 + try/catch 解析 + fallback 纯文本
2. **30KB 卡片限制** — 深度分析文本长时可能超限。对策：在 prompt 中限制每段分析字数（每 alert ≤ 200 字），card builder 中逐段截断
3. **只有 6 个图表** — 指标数量远不及竞品。对策：由 Gemini 基于现有数据做分析，不强行凑指标数；prompt 中明确"只分析提供的数据"
4. **飞书卡片 lark_md 无表格** — 对策：用等宽字体纯文本对齐，或飞书原生 `table` 组件（需要 JSON 2.0 table 组件，结构较复杂，优先纯文本对齐）

## 验证方案

1. 本地跑 `tsx src/cli.ts report` 验证 fetch+分析流程
2. 部署后 POST `/hermes/daily`（带 `X-Cron-Secret`）看群内卡片
3. 群里 @机器人 "日报" 看卡片格式
4. 检查卡片 JSON 大小 < 30KB
