# 修复：知识库+数据上下文合并 & 搜索结果优化

## 问题

1. **ask.ts wiki/data/闲聊三者互斥** — `if (hasWiki) {...} else if (dataContext) {...}` 永不同时存在，CoCo 无法关联分析
2. **搜索结果 2000 字符硬截断** — 无依据的防御代码。全部上下文（5 篇文档 + Amplitude 数据 + 对话历史）< 10000 token，Gemini 2.5 Flash 上限 1,000,000 token，远未触及
3. **搜索结果硬限制 5 篇** — 无 spec 要求，直觉值

## 修改文件（2 个）

### 1. `apps/hermes/src/ask.ts`

**改动：**

- 删除 `isDataQuestion()` 函数
- 始终并行 wiki + Amplitude（数据约 1.5s 可接受）
- 重构 userPrompt 为累积模式：wiki 块 + 数据块 + 问题 + 分析指令，不再互斥
- 分析指令：`"请结合全部上下文综合分析。不要逐字复读文档。先给出结论，再提供依据，结合深度分析提出务实的、理智的见解。"`
- System Prompt 暂不改动（待同事提供后单独更新）

### 2. `apps/hermes/src/wiki-cache.ts`

**两处改动：**

**a) 去掉 2000 字符硬截断**
- 删除 `section.content.slice(0, 2000)` — 完整段落直接透传
- 实际 token 量远在 Gemini 上限内，无需防御

**b) 取消 5 篇硬上限**
- `maxResults = 5` → `maxResults = 10`（仅防极端情况，实际不会触及）
- 新增：score 为 0 的低相关结果自动丢弃
- 同文档段数：2 → 4
