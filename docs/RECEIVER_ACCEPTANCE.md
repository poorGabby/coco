# CoCo 接收验收清单

验收原则：所有操作由接收方使用自己的公司账号和电脑完成，原交接人只观察和解释。

## A. 权限

- [ ] 能访问公司私有代码仓库并创建分支/PR。
- [ ] 能查看 GCP 项目和 Billing 状态。
- [ ] 能查看 Cloud Run、GCE、Cloud Build、Artifact Registry、Scheduler、Logging 和 GCS。
- [ ] 拥有飞书应用管理权限（已完成所有权转移后仍需验证权限）。
- [ ] 能访问 Amplitude、Stripe、Gemini/Google AI 等后台。

## B. 本地重建

- [ ] 从空目录 clone，不复制原交接人 `node_modules`。
- [ ] `npm ci` 成功。
- [ ] `npm run test:agent` 全部通过。
- [ ] 通过公司密钥系统取得测试配置，而不是复制原交接人的 `.env`。
- [ ] 能运行日报预览和一个测试问答。

## C. 生产理解

- [ ] 能说明 GCE 与 Cloud Run 各自职责。
- [ ] 能找到日报指标、收入口径、MCP 工具、Prompt 和飞书发送代码。
- [ ] 知道哪些状态在 VM、GCS 和内存中。
- [ ] 知道密钥存放位置和轮换负责人。

## D. 独立部署

- [ ] 接收方独立部署一个 Cloud Run revision。
- [ ] 健康检查和 MCP 验证通过。
- [ ] 接收方独立更新一次 GCE Agent。
- [ ] 飞书私聊、群聊 @、数据问答通过。
- [ ] 测试群日报卡片通过。
- [ ] 能演示 Cloud Run 和 GCE 的回滚办法。

## E. 收尾

- [ ] 轮换所有曾存在于原交接人电脑的密钥。
- [ ] 撤销旧服务账号 JSON key。
- [ ] 移除原交接人的非必要生产权限。
- [ ] 确认代码、云资源和账单均属于公司，而不是个人账号。
- [ ] 约定全量加密冷备的删除日期。
- [ ] 经理、交接人、接收技术负责人共同签字确认。
